--- title: "SI기업은 왜 AI플랫폼을 만들까? (feat. 양상추와 햄버거)" date: "2026-11-05" ---

나는 SI개발자다.


SI기업이란, 개발에 특화되지 않은 고객사에게 찾아가 그들의 업무에 맞춰 필요한 소프트웨어를 구축하는 회사다.

그리고 SI개발자는 각종 프로젝트가 수주 될 때마다 용병처럼 투입되어 고객사의 시스템을 개발하게 된다.


최근에 나는 AI를 활용해 조직이 일하는 방식을 개선하는 AX부서로 이전하게 되면서 처음으로 회사가 자체 개발했다는 AI시스템에 대해 공부하게 되었다.


회사의 AI플랫폼(이하 '뮤뮤')은 다음과 같은 특징을 가지고 있었다.

  1. 폐쇄망 기반 작동

    외부망 연결 없이 검색증강생성(RAG) 기술을 바탕으로 작동하여 보안이 중요한 기업 환경에 특화

  2. 전통적인 코딩 체계 지원

    금융 및 통신 등의 레거시 시스템 환경에서 단순 반복적인 코딩 업무를 줄이고 개발자가 핵심 비즈니스 로직에 집중하도록 도움

  3. 하드웨어 비용 절감

    거대한 초거대 AI(LLM)와 달리, 소형 언어 모델(sLLM)을 기반으로 함

  4. 사내 지식 자산 연동

    기업 내부의 표준 코딩 가이드라인, 기존 소스 코드 라이브러리, 개발 문서 등과 연계하여 작동

  • sLLM (small Large Language Model, 소형 언어 모델):

    LLM(대형 언어 모델)을 기반으로 특정 작업이나 영역에 특화된 파인튜닝(fine-tuned) 모델

  • RAG (Retrieval-Augmented Generation, 검색 증강 생성):

    인공지능이 외부 문서나 데이터베이스에 관련 정보를 먼저 찾아온 뒤(검색/Retrieval), 그 내용을 바탕으로 정확한 답변을 생성하는 AI 아키텍쳐


그런데 고객사 내부에서만 AI를 쓰는 게 목적이라면, 사내 서버에 언어 모델을 올려서 쓰는 방법도 있지 않을까?

이미 시중에는 유명한 회사(Meta, Google, OpenAI)들이 사내 서버로 내려받아 직접 실행할 수 있는 로컬 LLM을 지원하고 있었다.

고객이 원하는 게 폐쇄망에서 AI를 사용하는 것이라면, 로컬 LLM이 아니고 뮤뮤를 따로 도입해야할 이유는 무엇일까?


그러나, 나는 뮤뮤와 로컬 LLM과의 차이를 확인하고 나서 이 사업의 독특함을 깨닫게 되었다.

1. 개념적 정의 및 범위

  • 로컬 LLM (Local LLM):
    • 정의: Llama, Mistral, Gemma 등 오픈소스 모델의 가중치(Weights)를 다운로드하여 사용자 자신의 PC나 서버(온프레미스)에서 직접 추론(Inference)을 수행하는 것을 말한다.
    • 성격: 이는 하나의 엔진(Engine) 또는 컴포넌트(Component)다.
    • 한계: 모델 파일만으로는 사용자의 질문에 대한 정확한 내부 지식 기반 답변을 생성하지 못한다. 따라서, 별도의 프롬프트 엔지니어링이나 외부 데이터 연동 로직이 없으면 일반 상식 수준의 답변만 제공할 수 있다.
  • 뮤뮤:
    • 정의: 로컬 LLM(또는 클라우드 LLM)을 백엔드로 활용하되, 기업의 비공개 데이터를 안전하게 처리하고 검색하며, 업무 프로세스에 맞게 정제된 답변을 생성하는 통합형 AI 플랫폼이다.
    • 성격: 이는 솔루션(Solution) 또는 플랫폼(Platform)이다.
    • 특징: LLM을 '두뇌'로 삼되, 기억력(벡터 DB), 감각(검색 엔진), 행동 규칙(세이프가드)을 갖춘 완성된 시스템이다.

요약하면,

구분 로컬 LLM 뮤뮤
공통점 사내 서버에서 질문을 입력하고 답을 받을 수 있다.
본질 오픈소스 언어 모델 파일 (엔진) 언어 모델에 문서 검색·권한 관리 등을 더한 플랫폼 (솔루션)
개발 문서로 답하려면? 사용자가 관련 내용을 찾아 입력한다 연동된 문서에서 플랫폼이 관련 내용을 찾는다

2. 뮤뮤와 사내 클라우드 기반 로컬 LLM의 관계

여기서 핵심은 뮤뮤가 사내 클라우드 기반의 로컬 LLM을 활용하고 있었다는 것이었다.


  • 로컬 LLM (사내 클라우드 배포):
    • 단순히 "모델이 사내 서버에 있다"는 상태
    • 여전히 RAG 파이프라인, 문서 파싱, 벡터 DB 연동, 사용자 권한 관리, 프롬프트 템플릿 관리 등은 개발자가 직접 코드로 구현해야 한다.
  • 뮤뮤
    • 사내 클라우드에 배포된 로컬 LLM을 백엔드로 연결
    • 뮤뮤 플랫폼 자체가 사내 클라우드에 설치되거나, 사내 클라우드의 LLM 서버에 API로 연결
    • 뮤뮤가 제공하는 RAG 엔진, UI, 권한 관리, 감사 로그 등의 기능이 사내 LLM과 결합되어, 비개발자도 쉽게 사용할 수 있는 완성된 서비스가 된다.

⇒ 그러니까 로컬 LLM은 양상추고, 뮤뮤는 양상추를 포함해 이것저것 기능(RAG 엔진, UI, 권한 관리, 감사 로그 등)을 포함한 햄버거였다.


그리고, 뮤뮤는 다양한 오픈소서 로컬 LLM을 선택하여 적용할 수 있는 형태였다.

예시)

  • Llama 계열 (Meta)
  • Mistral 계열 (Mistral AI)
  • Gemma 계열 (Google)
  • etc ...

여기서 느낀 점은, LLM을 제대로 활용하지 못하거나 CLI같은 형태가 낯선 고객들에게 LLM을 제대로 뽕 뽑아먹을 수 있도록 패키지 형태로 플랫폼을 제공한다는 감상이 들었다.


마치 고등학교 봉사활동으로 어르신에게 '클릭'을 알려드렸던 경험이 떠올랐다.


개발자에겐 당연하지만, 개발 직무에서 벗어난 사람들에게도 접근성을 높여주는 것, 그리고 각종 인프라를 하나로 통솔하도록 하는 기능(오케스트레이션) 또한 뮤뮤의 강점으로 생각되었다.


확인해보니 이미 SI기업들 사이에서는 AI도구에 대한 경쟁이 이미 시작되고 있었다.

3. SI기업의 AI플랫폼 경쟁

1. 한국의 커스텀 수제버거 집

#국내_로컬_글로벌_AI_솔루션_벤더

아래의 SI기업들은 국내 고객사의 보안 정책과 업무 관행에 최적화된 플랫폼을 제공해주고 있다.


  • 롯데이노베이트 (Aimember)
    • 제품: 금융회사 내부망에서 임직원의 업무를 지원하는 생성형 AI 플랫폼
    • 특징: 롯데캐피탈 내부망에 자체 언어 모델 ‘아이멤버 Chat’과 검색증강생성(RAG) 기반 챗봇을 구축해, 외부 인터넷 연결 없이 이용할 수 있다.
  • KT DS (CodeBox-B.T.S)
    • 제품: 개발자의 코드 작성과 테스트를 지원하는 폐쇄망용 AI 코딩 솔루션
    • 특징: 자체 코딩 모델을 탑재한 일체형 장비를 고객사 내부에 설치해, 외부 인터넷 연결 없이 VS Code 같은 개발 환경에서 사용할 수 있다.

2. (참고) 최고급 양상추 농장

#글로벌_빅테크의_엔터프라이즈_AI_플랫폼 #글로벌_강자

이들은 자체 개발한 최상위 LLM(양상추)을 보유하고 있으며, LLM을 고객업무와 연결한 플랫폼(햄버거)도 제공한다.

일부는 폐쇄망 환경에서 모델을 운영하는 방식까지 지원한다.


  • Microsoft (Azure AI Foundry / Copilot Studio)
    • GPT-4 등 OpenAI 모델과 Azure 인프라를 결합한 가장 강력한 엔터프라이즈 플랫폼
    • Office 365(Word, Excel, Teams)와의 완벽한 연동이 최대 강점이다. "문서 요약", "회의록 생성" 등 업무 도구 내에서의 AI 활용이 가장 자연스럽다.
    • 온프레미스(완전 사내 서버) 배포 시 제약이 많거나, 특정 하드웨어/라이선스 비용이 높을 수 있다.
  • Google Cloud (Gemini on GDC air-gapped)
    • Google Distributed Cloud(GDC)에서 Gemini 모델을 실행하는 구축형 솔루션
    • 고객사 데이터센터에 구축해 외부 인터넷에 연결하지 않고도 Gemini를 사용할 수 있다.
  • AWS (Amazon Bedrock / SageMaker)
    • 다양한 LLM(Anthropic Claude, Meta Llama, Amazon Titan 등)을 하나의 API로 호출할 수 있는 모델 아그노스틱(모델 비종속) 플랫폼
    • "어떤 모델을 쓸지 자유롭게 고를 수 있다"는 유연성이 가장 큰 장점이다. "모델 오케스트레이션" 개념과 가장 유사하다.
    • 개발자 친화적이며, 비개발자가 쉽게 사용할 수 있는 "완성된 업무 솔루션"보다는 개발 인프라(IaaS/PaaS) 성격이 강하다.

4. 마지막 의심


1년 전, Claude가 웹사이트 레이아웃을 자동으로 디자인해주는 신기술을 발표했다.

친구는 이 기능을 활용해서 웹사이트의 테마, 용도, 사용 목적을 입력하면 웹사이트를 완성시켜주고, 세세한 요소는 직접 편집 가능한 플랫폼을 완성했다.

친구가 AI플랫폼을 완성하기까지는 한 달이 꼬박 걸렸다.


그 다음날, Anthropic이 Claude의 새 기능을 발표했다.

Claude는 친구 아이디어를 더 완벽하게 구현한 형태로 신기능을 공개한 것이다.

친구가 애써 만든 플랫폼을 굳이 따로 쓸 이유가 하루 만에 사라진 것이다.


그래서 양상추와 햄버거의 차이를 이해하고 나서도 의심이 하나 남았다.

뮤뮤를 쓰는 이유가 ‘지금은 모델만으로 하기 번거로운 일을 대신해 준다’는 데 있다면, 그 ‘지금’은 얼마나 오래갈까?

반대로 내일 Claude에 비슷한 기능이 생겨도, 고객이 여전히 뮤뮤를 선택할 이유는 뭘까?
