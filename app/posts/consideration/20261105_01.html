--- title: "SI기업은 왜 AI플랫폼을 만들까? (feat. 양상추와 햄버거)" date: "2026-11-05" ---

나는 SI개발자로 일한지 6년 차이다. SI기업은 개발에 특화되지 않은 고객사에게 찾아가 그들의 업무에 맞춰 필요한 소프트웨어를 구축하는 회사다. 그리고 SI개발자는 각종 프로젝트가 수주 될 때마다 투입되는 용병 개발자로 일한다는 의미다.

최근에 나는 AI를 활용해 조직이 일하는 방식을 개선한다는 AX부서로 이전하면서, 처음으로 회사가 자체개발했다는 AI시스템에 대해 공부하게 되었다.

회사의 AI플랫폼(이하 '뮤뮤')은 다음과 같은 특징을 가지고 있었다.

  1. 폐쇄망 기반 작동

    외부망 연결 없이 검색증강생성(RAG) 기술을 바탕으로 작동하여 보안이 중요한 기업 환경에 특화

  2. 전통적인 코딩 체계 지원

    금융 및 통신 등의 레거시 시스템 환경에서 단순 반복적인 코딩 업무를 줄이고 개발자가 핵심 비즈니스 로직에 집중하도록 도움

  3. 하드웨어 비용 절감

    거대한 초거대 AI(LLM)와 달리, 소형 언어 모델(sLLM)을 기반으로 함

  4. 사내 지식 자산 연동

    기업 내부의 표준 코딩 가이드라인, 기존 소스 코드 라이브러리, 개발 문서 등과 연계하여 작동

  • sLLM (small Large Language Mode, 소형 언어 모델):

    LLM(대형 언어 모델)을 기반으로 특정 작업이나 영역에 특화된 파인튜닝(fine-tuned) 모델

  • RAG (Retrieval-Argumented Generation, 검색 증강 생성):

    인공지능이 외부 문서나 데이터베이스에 관련 정보를 먼저 찾아온 뒤(검색/Retrieval), 그 내용을 바탕으로 정확한 답변을 생성하는 AI 아키텍쳐

가장 첫번째로 들었던 의문은, SI사업을 진행하는 고객사의 폐쇄성을 지켜준다 하더라도, AI자체의 성능은 범용 LLM을 이기지 못할 텐데 폐쇄성이라는 장점만으로 고객에게 어필이 되는걸까 하는 생각이 들었다.

나는 해당 사업이 유명한 범용LLM(ChatGPT, Claude, Gemini)과의 차이를 확인하고 나서, 이 사업의 독특함을 깨닫게 되었다.

1. 개념적 정의 및 범위

  • 로컬 LLM (Local LLM):
    • 정의: Llama, Mistral, Gemma 등 오픈소스 모델의 가중치(Weights)를 다운로드하여 사용자 자신의 PC나 서버(온프레미스)에서 직접 추론(Inference)을 수행하는 것을 말한다.
    • 성격: 이는 하나의 엔진(Engine) 또는 컴포넌트(Component)에 불과하다.
    • 한계: 모델 파일만으로는 사용자의 질문에 대한 정확한 내부 지식 기반 답변을 생성하지 못한다. 따라서, 별도의 프롬프트 엔지니어링이나 외부 데이터 연동 로직이 없으면 일반 상식 수준의 답변만 제공할 수 있다.
  • 뮤뮤:
    • 정의: 로컬 LLM(또는 클라우드 LLM)을 백엔드로 활용하되, 기업의 비공개 데이터를 안전하게 처리하고 검색하며, 업무 프로세스에 맞게 정제된 답변을 생성하는 통합형 AI 플랫폼입니다.
    • 성격: 이는 솔루션(Solution) 또는 플랫폼(Platform)이다.
    • 특징: LLM을 '두뇌'로 삼되, 기억력(벡터 DB), 감각(검색 엔진), 행동 규칙(세이프가드)을 갖춘 완성된 시스템이다.

요약하면,

구분 로컬 LLM 뮤뮤
본질 오픈소스 언어 모델 파일 (엔진) 기업용 AI 지식 관리 플랫폼 (솔루션)
핵심 기능 텍스트 생성 및 이해 RAG 기반 지식 검색, 업무 자동화, 보안 관리
데이터 연동 개발자가 직접 RAG 파이프라인 구축 필요 내장된 RAG 엔진으로 자동 연동 및 관리
사용 대상 AI 개발자, 데이터 사이언티스트 비즈니스 사용자, IT 관리자, 개발자
보안/권한 모델 파일 수준 접근 제어만 가능 사용자별 권한, 감사 로그, 데이터 격리 등 기업급 보안
유지보수 모델, 환경, 하드웨어 직접 관리 플랫폼 단위 관리, 벤더 지원
활용 난이도 높음 (개발 역량 필요) 낮음~중간 (설정 중심, 개발 최소화)

2. 뮤뮤와 사내 클라우드 기반 로컬 LLM의 관계

여기서 핵심은 뮤뮤가 사내 클라우드 기반의 로컬 LLM을 활용하고 있었다는 것이었다.

  • 로컬 LLM (사내 클라우드 배포):
    • 단순히 "모델이 사내 서버에 있다"는 상태
    • 여전히 RAG 파이프라인, 문서 파싱, 벡터 DB 연동, 사용자 권한 관리, 프롬프트 템플릿 관리 등은 개발자가 직접 코드로 구현해야 한다.
  • 뮤뮤
    • 사내 클라우드에 배포된 로컬 LLM을 백엔드로 연결
    • 뮤뮤 플랫폼 자체가 사내 클라우드에 설치되거나, 사내 클라우드의 LLM 서버에 API로 연결
    • 뮤뮤가 제공하는 RAG 엔진, UI, 권한 관리, 감사 로그 등의 기능이 사내 LLM과 결합되어, 비개발자도 쉽게 사용할 수 있는 완성된 서비스가 된다.

⇒ 그러니까 로컬 LLM은 양상추고, 뮤뮤는 양상추를 포함해 이것저것 기능(RAG 엔진, UI, 권한 관리, 감사 로그 등)을 포함한 햄버거였다.


그리고, 뮤뮤는 다양한 오픈소서 로컬 LLM을 선택하여 적용할 수 있는 형태였다.

예시)

  • Llama 계열(Meta)
  • Mistral(Mistral AI)
  • Gemma(Google)
  • etc ...

3. SI기업의 AI플랫폼 경쟁

확인해 본 바로, 실제로 타 SI기업들도 업무에 자체개발한 AI플랫폼을 개발하는 중이었다.
